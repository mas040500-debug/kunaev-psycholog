# Сервер админки

Маленькая программа, которая делает три вещи: пускает по паролю, кладёт правки
в репозиторий и принимает картинки. Живёт на Cloudflare Workers — бесплатного
тарифа хватает с большим запасом (100 000 запросов в день; админка делает
десятки).

**Зачем он вообще нужен.** Сайт статический, у него нет своего сервера. Чтобы
психолог мог сохранять правки, кто-то должен иметь право писать в репозиторий.
Отдать это право браузеру нельзя: доступ утечёт первому, кто откроет исходники
страницы. Поэтому доступ лежит здесь, а браузер только просит: «сохрани вот
это». Психолог при этом не заводит GitHub и не видит никаких токенов.

---

## Что понадобится

Три бесплатных вещи, все создаются по ходу:

1. Аккаунт Cloudflare.
2. Токен GitHub с правом писать **только в этот репозиторий**.
3. Node.js на компьютере (уже нужен для сборки сайта).

---

## Два пути

**Через панель Cloudflare, без терминала** — кликами в браузере. Годится, если
Node на компьютере нет или возиться с командной строкой не хочется. Пароли
считает страница `admin/setup.html`, открытая в браузере.

**Через терминал** (`wrangler`) — быстрее, если Node уже стоит, и удобнее для
повторных выкладок.

Ниже сначала путь без терминала, потом команды для второго.

---

## Путь без терминала

### 1. Создать воркер

Панель Cloudflare → в левом меню **Вычислить** → **Workers и Pages** →
**Create** → вкладка **Worker** → имя `kunaev-admin` → **Deploy**.

Создастся заготовка «Hello World» — её содержимое сейчас заменим.

### 2. Вставить код

На странице воркера → **Edit code**. Выделить всё в редакторе, удалить и
вставить содержимое файла `worker/src/index.js` целиком. → **Deploy**.

### 3. Настройки

Вкладка **Settings** → **Variables and Secrets**.

Три обычные переменные (Type: Text):

| имя | значение |
|---|---|
| `REPO` | `mas040500-debug/kunaev-psycholog` |
| `BRANCH` | `main` |
| `ALLOWED_ORIGINS` | `https://mas040500-debug.github.io` |

Три секрета (Type: **Secret**, значение после сохранения не показывается):

| имя | значение |
|---|---|
| `GITHUB_TOKEN` | токен из шага 4 |
| `AUTH_USERS` | результат из `admin/setup.html` |
| `SESSION_SECRET` | любая длинная случайная строка |

### 4. Токен GitHub

См. раздел «Токен GitHub» ниже — он одинаков для обоих путей.

### 5. Пароли

Открыть `admin/setup.html` (на сайте — `/admin/setup.html`), заполнить почту и
пароль, нажать «Добавить человека», скопировать результат в секрет
`AUTH_USERS`.

Пароль считается прямо в браузере и никуда не отправляется — в секрет попадает
только отпечаток.

### 6. Подключить админку

Адрес воркера виден на его странице, вида
`https://kunaev-admin.ЧТО-ТО.workers.dev`. Вписать его в `admin/config.js`,
закоммитить, запушить.

## Выкладка через терминал

### Токен GitHub

GitHub → Settings → Developer settings → **Personal access tokens → Fine-grained
tokens** → Generate new token.

- **Repository access** → Only select repositories → `kunaev-psycholog`
- **Permissions → Repository permissions → Contents** → **Read and write**
- Срок — на своё усмотрение; когда истечёт, админка перестанет сохранять, и
  токен надо будет выпустить заново.

Скопируйте токен сразу: второй раз GitHub его не покажет.

> Права ровно на один репозиторий и только на содержимое — это осознанно.
> Даже если токен утечёт, им нельзя тронуть другие ваши репозитории.

### 2. Пароли для входа

Для каждого, кто будет заходить в редактор:

```
node worker/make-user.mjs psy@example.com 'придуманный-длинный-пароль'
```

Команда напечатает запись без самого пароля — обратно его из неё не достать.
Если людей двое, соберите обе записи в один массив.

Пароль придумайте длинный, лучше из нескольких слов: это единственный замок
на редакторе.

### 3. Выложить

Из папки `worker/`:

```
npx wrangler login          # откроется браузер, вход в Cloudflare
npx wrangler deploy         # первая выкладка
```

Затем три секрета — каждая команда спросит значение и не покажет его на экране:

```
npx wrangler secret put GITHUB_TOKEN      # токен из шага 1
npx wrangler secret put AUTH_USERS        # массив из шага 2
npx wrangler secret put SESSION_SECRET    # любая длинная случайная строка
```

Случайную строку для последнего можно взять так:

```
node -e "console.log(crypto.randomUUID() + crypto.randomUUID())"
```

Секреты хранятся у Cloudflare и в репозиторий не попадают. В `wrangler.toml`
лежат только несекретные настройки — он публичный.

### 4. Подключить админку

`wrangler deploy` напечатает адрес вида
`https://kunaev-admin.НАЗВАНИЕ.workers.dev`. Впишите его в `admin/config.js`:

```js
export const API_BASE = 'https://kunaev-admin.НАЗВАНИЕ.workers.dev';
```

Закоммитьте и запушьте. Всё: в редакторе появится вход, кнопка «Опубликовать»
заработает, у выбора картинки появится загрузка с компьютера.

### 5. Проверить

Откройте админку, поменяйте любой текст, нажмите «Опубликовать». Через
минуту-другую правка должна появиться на сайте: воркер кладёт в репозиторий
`content/site.json`, а `rebuild.yml` пересобирает по нему страницу.

## Как это устроено

```
браузер психолога → воркер → GitHub → Actions пересобирают → сайт
   (пароль)        (токен)
```

Воркер знает четыре адреса:

| адрес | что делает |
|---|---|
| `POST /login` | почта и пароль → токен на 30 дней |
| `GET /me` | действует ли ещё токен |
| `POST /publish` | кладёт контент в `content/site.json` |
| `POST /upload` | кладёт картинку в `assets/uploads/` |

Токен подписан секретом сервера: подделать его нельзя, а проверка не требует
хранить сессии.

## Что сделано ради безопасности

- **Пароль не хранится** — только отпечаток PBKDF2 с солью, 210 000 повторений.
- **Ответ при неверном входе одинаковый** независимо от того, заведена почта
  или нет, и отпечаток считается всегда: иначе по времени ответа можно было бы
  перебрать список адресов.
- **Сравнение за постоянное время** — обычное `===` выдаёт длину совпавшего
  начала.
- **Запросы принимаются только с адреса админки.** Звёздочки в CORS нет:
  иначе редактор можно было бы дёргать с чужого сайта.
- **Контент проверяется на входе.** Сломанный не попадёт в репозиторий и не
  уронит сборку.
- **Имя картинки собирается заново** из букв и цифр — `../../` не пролезет.
- **Текст ошибок наружу общий.** В сообщении от GitHub может оказаться лишнее.
- **Ссылки в контенте проверяются по схеме** (в сборщике): `javascript:` в
  поле ссылки превращается в `#`.

Ограничение перебора пароля в воркере простое: счётчик в памяти, который
сбрасывается при перезапуске и не общий для машин. Это помеха, а не защита.
Настоящий лимит стоит включить на стороне Cloudflare — Security → WAF → Rate
limiting rules, на путь `/login`.

## Локальная проверка

Не трогая ни Cloudflare, ни GitHub:

```
node worker/test.mjs      # 26 проверок: вход, доступ, публикация, картинки
node worker/dev.mjs       # тот же воркер на localhost:8787, GitHub в памяти
```

Для второго впишите в `admin/config.js` адрес `http://localhost:8787`, поднимите
статику (`python3 -m http.server 8765`) и заходите под `admin@local` с паролем
`локальный-пароль-1234`. **Перед коммитом верните `API_BASE` обратно.**
