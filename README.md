# Владимир Кунаев — психолог

Лендинг психолога: готовый сайт, дизайн-система и блоки для Тильды.

**Живая страница:** https://mas040500-debug.github.io/kunaev-psycholog/

**Сайт лежит в корне** — `index.html`, `styles.css`, `assets/`. Готовая страница
открывается двойным кликом, и репозиторий сразу пригоден для GitHub Pages
(Settings → Pages → Deploy from a branch → `main` / `root`).

---

## Что внутри

| путь | что это |
|---|---|
| `index.html`, `styles.css`, `assets/` | **готовый сайт**, одна страница, 8 секций |
| `content/site.json` | **контент страницы** — тексты, картинки, порядок блоков |
| `build/` | сборщик: собирает `index.html` из контента и шаблонов блоков |
| `design-system/` | токены дизайн-системы: `tokens.css`, `tokens.json`, описание решений |
| `tilda-blocks/` | та же вёрстка, порезанная на блоки **T123** для Тильды |

Сайт и блоки Тильды — одна и та же вёрстка в двух упаковках. Правки вносятся в оба
места, либо выбирается что-то одно.

---

## Контент и сборка

`index.html` больше не правится руками — он собирается из `content/site.json`:

```
node build/build.mjs                                   # собрать index.html
node build/build.mjs --check                            # проверить, что он не разошёлся с контентом
node build/build.mjs --content=черновик.json --out=_превью.html   # собрать из другого файла
```

Проверка `--check` стоит в CI: если кто-то поправит разметку напрямую, сборка это
поймает, иначе следующий запуск молча затрёт правку.

**Что где живёт.** В `content/site.json` — только то, что меняет владелец сайта:
тексты, ссылки, картинки, состав и порядок блоков, флаг `visible`. Геометрия —
кривые SVG, размеры карточки героя, наклоны, проценты — намеренно осталась в
шаблонах `build/blocks.mjs`: это часть дизайна, а не контент. Шапка, подвал и
скрипты лежат в `build/partials/` как есть, там нечего редактировать.

Замена разметки на сборку проверена: собранная страница совпала с прежней
попиксельно на 1440, 768 и 390 px.

### Блоки

У каждого блока есть `bg` (`surface` / `second-soft` / `page`) и `visible`.
Порядок блоков в массиве — порядок на странице.

**Рваные края между секциями сборщик считает сам** по фону соседей: край нужен
там, где фон меняется. Поэтому блок можно спрятать или переставить, и переходы
останутся правильными. Флаг `tearInto: "next"` переключает край на зеркальный
вариант — блок рвётся вниз сам, а не сосед сверху; так сделано у героя и у
«Принципов работы».

Семь блоков страницы существуют в одном экземпляре — их состав задан дизайном.
Выравнивание есть и у них — у шести из семи: у бегущей строки выравнивать
нечего, она едет через весь экран. Двигается текстовая часть блока (колонка
героя, шапка «Принципов», текст рядом с папкой диплома), а не карточки и не
фотографии: их положение — часть макета.
Простые блоки можно добавлять сколько угодно и куда угодно:

| тип | что это |
|---|---|
| `text` | заголовок с текстом, по левому краю или по центру |
| `image` | картинка с подписью |
| `media` | картинка с текстом, картинка слева или справа |
| `quote` | цитата с автором |
| `cta` | заголовок, текст и кнопка |
| `spacer` | пустой отступ, три высоты |

Поля каждого типа описаны в `build/schema.mjs` — по этому файлу админка потом
построит формы, чтобы добавление блока не требовало правок в трёх местах.

### Шапка, меню и подвал

Лежат в `content/site.json` рядом с блоками. Меню одно на всю страницу: из
списка `nav` собираются и верхнее меню, и мобильная шторка-гамбургер, и меню
в подвале. Пункт добавляется один раз и появляется во всех трёх местах.

**Якоря есть у каждого блока.** `id` ставится всем: `anchor`, если он задан в
контенте, иначе `id` блока. Раньше `id` был только у четырёх блоков, и сослаться
из меню на остальные было нельзя — а завести якорь самому владелец сайта не
может, это уже не контент.

В админке поля «Куда ведёт» (меню, кнопка героя, призыв) — не строка ввода, а
выбор из блоков страницы плюс «Своя ссылка». Строка требовала знать, что писать
`#about`, и откуда взялось это слово, не было видно нигде.

Переключатель «Тип ссылки» намеренно **не** вызывает перерисовку формы: это
выбор способа ввода, а не правка контента. С перерисовкой поле возвращалось в
режим «блок» — по пустому значению режим неотличим от нового пункта.

### Оформление простых блоков

У блоков с текстом (`text`, `media`, `quote`, `cta`) есть `style`: цвет, шрифт,
размер, выравнивание и отступы внутри блока. У «Картинки» из этого набора есть
только выравнивание — красить и укрупнять ей нечего.

Выравнивание — единственная ступень, у которой **заготовка своя у каждого типа**
(`ALIGN_DEFAULTS` в `build/schema.mjs`): цитата, призыв и картинка задуманы по
центру, текст и «картинка с текстом» — от левого края. Общее значение сдвинуло
бы половину блоков при первом же открытии формы. Класс `is-align-*` ведёт сразу
и текст, и колонку, и картинку: иначе центрированный заголовок остался бы висеть
над колонкой, прижатой влево.

Это **ступени, а не произвольные значения**: цвета — только те, что читаются на
всех трёх фонах, шрифта два, размера три, отступа три. Свободный выбор через
месяц дал бы серый текст на сиреневом и восемь разных кеглей на одной странице,
а разгребать это пришлось бы дизайнеру.

Рукописный шрифт идёт с поправкой на кегль (`--blk-scale`): при одном и том же
размере он мельче на глаз, и без поправки выбор шрифта менял бы ещё и видимый
размер текста.

Ширина текста и вся остальная типографика заданы в CSS, а не в контенте: что бы
в блок ни написали, он остаётся в общей сетке страницы.

## Редактор (`admin/`)

Страница `admin/index.html` — редактор контента: список блоков с перетаскиванием,
скрытием и удалением, формы полей и живой предпросмотр.

Он **не открывается двойным кликом**: модули и `fetch` требуют сервера. Локально —
любой статический сервер из корня проекта, например:

```
python3 -m http.server 8765     # затем http://localhost:8765/admin/
```

**Предпросмотр — не макет, а та же страница.** Он собирается теми же модулями
(`build/assemble.mjs` → `build/blocks.mjs`), что и живой сайт, поэтому разойтись
с результатом не может. Формы строятся по `build/schema.mjs`.

Две вещи, которые легко сломать обратно, если не знать:

- Внутри предпросмотра стоит **абсолютный** `<base href>`. Относительный внутри
  `srcdoc` браузер считает от `about:srcdoc`, и стили с картинками отваливаются.
- Уменьшение рамки сделано через `zoom`, а не `transform: scale()`. С `transform`
  содержимое рамки перестаёт отрисовываться — остаются бледные призраки текста.

### Вход, публикация и картинки

Редактор работает в двух режимах, и переключает их одна строка в
`admin/config.js`.

**Без сервера** (`API_BASE = ''`) — правки живут в браузере, публикация
недоступна, картинки выбираются из уже загруженных. Это рабочий режим: в нём
можно спокойно всё показывать и обсуждать.

**С сервером** — редактор закрыт входом: до него видно только форму пароля,
интерфейс и панель кнопок появляются после входа. Дальше «Опубликовать» кладёт
контент в репозиторий, а картинки загружаются с компьютера.

Вход при запуске отменить нельзя (кнопка «Отмена» скрыта, Esc перехвачен) —
отменять некуда, за окном пусто. При публикации, наоборот, отмена нужна, и там
диалог ведёт себя по-прежнему.

Это **ширма, а не замок**: страница редактора лежит на статическом хостинге, и
её разметку при желании достанут и без входа. Настоящая защита — пароль на
публикации, он проверяется сервером. Ширма убирает случайного зрителя, которому
странно видеть чужую панель управления. Как выложить
сервер — [`worker/README.md`](worker/README.md).

Доступ к репозиторию живёт только в воркере и в браузер не попадает никогда:
психолог не заводит GitHub и не видит токенов.

Цепочка публикации: админка → воркер кладёт `content/site.json` в репозиторий →
`rebuild.yml` пересобирает `index.html` → GitHub Pages выкладывает.

Картинки ужимаются в браузере до 1600px по длинной стороне ещё до отправки:
иначе фотография с телефона на 6 МБ уехала бы в репозиторий как есть.

Проверки воркера: `node worker/test.mjs`.

привязанные к позициям карточек, они не перетекают.

## Шрифты

**Arimo** — основной, подключён с Google Fonts. Полная кириллица.

**Good Vibes Pro** — рукописный акцент (строка в герое, водяной знак «комфорт», подпись
на фото и на бирке диплома). На Google Fonts его нет — самохостится из
`assets/fonts/GoodVibesPro.ttf` (кириллическая версия), `@font-face` в `styles.css`
подключает его напрямую.

**Great Vibes** в стеке ниже — не альтернатива, а страховка на случай, если `.ttf` не
подгрузится: у него есть кириллица, но метрики другие, строки в герое поедут. Именно
поэтому размер скрипта на планшете и мобильном подобран так, чтобы фраза «комфортных
условий» влезала в одну строку (56px и 28px) при любом из двух шрифтов: переносить её
нельзя — обе гарнитуры для этого узла недоступны для программного измерения ширины.

## Поиск и ссылки

Всё, что касается выдачи и пересланных ссылок, собирается из одного поля —
`meta.siteUrl` в контенте (в админке это «Сайт в поиске» → «Адрес сайта»):

| что | где | зачем |
|---|---|---|
| `<link rel="canonical">` | в странице | какой адрес считать главным |
| `og:url`, `og:image` | в странице | карточка ссылки в мессенджерах — адреса **полные**, иначе Telegram не найдёт картинку |
| `<script type="application/ld+json">` | в странице | кто это и как связаться, прямым текстом; телефон и мессенджеры берутся из блока «Контакты», чтобы не разъехаться с ним |
| `robots.txt`, `sitemap.xml` | в корне, **собираются** | при переезде на свой домен обновятся сами |

Готовыми эти два файла не лежат намеренно: разъехавшаяся карта сайта хуже
отсутствующей — она уводит поисковик на адрес, которого уже нет.

Редактор закрыт от поисковиков дважды: `Disallow: /admin/` в `robots.txt` и
`<meta name="robots" content="noindex">` на самих страницах админки. Второе
надёжнее — `robots.txt` лишь просьба.

**Чего разметка не делает.** Она помогает поисковику разобрать страницу, но не
приводит людей. Позиции в выдаче берутся из текста, ссылок с других сайтов и
карточек в справочниках — из работы, которую разметка не заменяет.

## Что нужно заменить перед публикацией

1. **Телефон, Telegram, WhatsApp** в секции «Контакты» — каждый в двух местах: в видимом
   тексте и в `href`. В `wa.me` номер пишется без плюса и скобок.
2. **Политика конфиденциальности** в подвале — сейчас `href="#"`.

## Фотографии

`assets/portrait-hero.png` и `assets/portrait-about.png` выгружены из Figma в том
размере, в котором они там лежат (1:1 к макету). Для экранов с высокой плотностью
пикселей лучше положить оригиналы в двойном разрешении под теми же именами — вёрстку
менять не придётся.

`assets/docs/` — семь сканов настоящих дипломов и сертификатов Владимира: диплом МГУ,
переподготовка и повышение квалификации с приложениями, сертификат МГУ. Показываются
в карусели секции «Образование» — см. ниже.

## Карусель документов («Образование»)

Папка с кольцами, зажимом и загнутым углом собрана вёрсткой (CSS + inline SVG), а не
картинкой — так бумажка с подписью масштабируется вместе с папкой на любом экране.
Скан документа и подпись на бумажке («Диплом МГУ» / «Факультет психологии» и т. д.)
переключаются синхронно стрелками, без перезагрузки страницы — логика в конце
`index.html`, массив `docs` в скрипте карусели. Стрелки листают по кругу, следующие
сканы подгружаются заранее, чтобы переключение было без задержки.

Чтобы добавить или заменить документ: положить скан в `assets/docs/`, добавить/поменять
объект в массиве `docs` (`src`, `note`, `sub`, `alt`).

## Проверка

```sh
# сайт
open index.html          # или просто двойной клик

# блоки Тильды — склеить в одно превью
cd tilda-blocks && sh build-preview.sh
```

Windows нельзя сузить меньше ~500px, и обычный ресайз даёт обманчивую картину.
